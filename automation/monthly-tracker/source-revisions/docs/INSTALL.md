10. Native concurrency/recovery gate: test simultaneous manual runs, archive success followed by table failure, execution stop/replay and a lost/corrupted evidence file. Exactly-once creation is NOT claimed. Until this gate is resolved, run checks serially and never overlap manual execution with the daily time. A lost existing evidence file needs operator repair; the sequential dedup path does not download it again automatically. Keep human review decisions in the separate register, not in writable observation columns.
11. Record native workflow ID, n8n version, node count, execution IDs, table IDs, archive hashes, persistence/replay evidence and the native acceptance disposition in the handoff. The approved design includes daily checks; the currently delivered artifact does not prove activation. At the next real scheduled run verify that it fired at 08:00 America/Jamaica, completed all expected sources and saved the right records. A manual run does not prove scheduling.

## Future months

The monitor reads the live published tracker, so it discovers newly published months automatically without reimporting the workflow. It deliberately does not invent their as-published byte identity. When a month first appears without a baseline it saves a BASELINE_REQUIRED observation/candidate and flags the run for attention. Retrieve the exact frozen source from that month's existing approved stored package, verify its recorded SHA-256 and its linkage to the final publication receipt, then append one baseline row in the NEW baseline table. Do not hash the latest Ministry download and silently call it the original. No monthly tracker Sheet update is required for this intake.

Automatic baseline intake from the existing publisher is a possible later integration. It is not silently added here because it requires trusted published-package/receipt linkage and current native export validation. Until that integration is separately verified, this one baseline-row intake is the controlled monthly step. The workflow keeps detecting unverified new versions while flagging incomplete baseline coverage; it never reports a fully verified no-change run for them.

## Rollback

Disable the new schedule and deactivate this new workflow. Export its definition and retain private baselines, observations and archived evidence for audit. Remove only the new optional failure-handler binding if one was added. Do not delete evidence, reset production history, rerun publication or modify any existing workflow. The website/live feed requires no rollback because this package does not change either.
