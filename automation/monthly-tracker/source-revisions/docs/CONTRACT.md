# Detection and review contract

Scope constant: JIF_MONTHLY_TRACKER_SOURCE_REVISIONS_ONLY. The only external reads are the fixed public tracker/extras CSV URLs, the Ministry CGO listing, validated HTTPS www.mof.gov.jm/wp-content/uploads/*.xlsx URLs, the two configured private tables and newly archived Drive bytes. Source URLs reject query strings, path traversal and alternate authorities. Redirects are disabled for Ministry listing and workbook identity. Only the two fixed anonymous Google CSV reads follow at most three redirects for export delivery. No HTML is interpreted as a workbook.

Workflow configuration mode REPORT_ONLY has no transports. OBSERVE requires isolated table IDs plus the exact new evidence-folder ID. HTTP metadata cannot authorize a new destination. A valid XLSX-shaped payload must be HTTP 200, 100–10,000,000 bytes, ZIP-local-header/EOCD present and contain the workbook member name. This is a basic container check, not full ZIP/XML integrity, malware scanning or spreadsheet calculation. The size check is post-download; no claim is made that n8n streamed only that many bytes. Semantic review performs the stricter bounded ZIP/openpyxl checks offline.

Observation classifications: UNCHANGED, SOURCE_BYTES_CHANGED, SOURCE_LINK_CHANGED, BASELINE_REQUIRED, CHECK_FAILED. They are detection outcomes, not project approval states or editorial decisions. All non-UNCHANGED cases require review. A case ID binds scope, period, source URL and observed hash (or failure code); check_key binds period/URL and ensures complete coverage. Evidence names bind month/hash. First_seen is retained on coherent sequential replay; last_seen is updated. Duplicate observation rows, conflicting identity or backward timestamps fail closed. All expected source results must be present exactly once.

Data Table upsert is not assumed to provide a unique database constraint under concurrency. Stable logical case IDs avoid treating repeated detections as new editorial cases, but native simultaneous-run and interrupted-write acceptance remain open. A candidate upload followed by a failed log write may leave an orphan archive and cause another upload on retry; reconcile by hash and preserve the evidence rather than deleting blindly. No retry can publish financial data because the graph has no publisher path.

The reference baseline provenance matters: May/June have independently matched accepted Drive archive bytes. April/July/August are verified snapshot matches to published inputs; this does not assert a separate accepted historical archive byte identity. The seeded hashes/amount checks are evidence as of October 28, not permission to restate history.

Human review register fields: case ID, reporting month, original and candidate source identities/hashes, date detected, source listing/file-record dates where independently verified, semantic review, changed KPIs/formulas/signs/statuses/narratives, reviewer, decision, decision date and evidence/release links. Detection time, attachment record time, source listing date and JIF publication/update date are separate. No timestamp is manufactured for first availability.

April–June register seed records OBSERVED_VERSION_DIFFERENCE with editorial_decision=PENDING. Semantic reconciliation is complete; financial adoption is false. Website policy currently RETAIN_AS_PUBLISHED_WITH_REVISION_NOTE, already released in PR41. This does not predetermine the later adoption decision. April raises two balance actuals; May's five repairs leave published YTD results correct; June changes two budgets and the fiscal narrative. No individual status changes.

Adoption policy approved in this planning scope: verified applicable official revisions should proceed through human review toward a clearly labelled revised assessment, preserving the original publication. This is not approval of any particular later figure. A coordinated future correction covers data, gaps, rankings, explanations, source register, revised receipts and correction history together. The monitor cannot approve or perform it.

Public revision record schema is supplied as review data, not automatically connected to the website. The existing PR41 source notes already expose the known differences. Any future public revision-history expansion must use approved register records and preserve the existing feed/workflow contract; no website deployment is performed by this package.
