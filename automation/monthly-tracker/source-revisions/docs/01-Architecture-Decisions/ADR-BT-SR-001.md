# ADR-BT-SR-001: Isolated monthly tracker source revision observation

Context: April–June official CGO variants have real cell/formula differences. The existing monthly monitor identifies new periods and hands off preparation; using that same trigger to silently restate historical months would blur approved publications and later evidence.

Decision: retain the existing monthly chain, feed, original receipts and Spending Explorer. Add a new inactive detection workflow with a manual trigger and disabled daily schedule. Read public published periods and the official listing, compare original/published/listed exact-byte identities against explicit private baselines, save candidate binaries in a new private folder with hash readback, and record observations in a new Data Table. A second new baseline table is populated from trusted publication source evidence. No public writer, subscriber sender or child-workflow call exists. Human decisions remain in a separate revision register; semantic review uses the restricted offline workbook evaluator.

Consequences: this makes source revisions visible without granting publication authority. New months are automatically discovered but require one verified baseline row from their frozen published package until a trusted automatic intake bridge is separately implemented. Native table/Drive credential binding, replay/concurrency and scheduled-execution acceptance remain required. Sequential case deduplication is tested; distributed exactly-once creation is not claimed. Existing production credentials, guard/ledger tables and workflows are untouched. All artifacts and test/provenance limits are retained in the dedicated Drive handoff/package.
